# Study Space 구현 실행 프롬프트

첨부된 `study-space-prompt.md`와 `design.md`를 먼저 끝까지 읽고, 해당 문서를 기준으로 실제 작동하는 Study Space 웹 애플리케이션을 구현해줘.

## 필수 기술 및 배포 구성
- 웹앱: Next.js + TypeScript
- 스타일: Tailwind CSS 및 접근성 있는 UI 컴포넌트
- 호스팅 및 서버 측 기능: Vercel
- 인증 및 PostgreSQL 데이터베이스: Supabase
- 코드 저장 및 배포 연동: GitHub
- 배포 목표: Vercel에 배포할 수 있는 상태로 완성

별도의 VPS, EC2, 상시 실행 서버는 추가하지 마. Vercel Functions/Route Handlers/Server Actions가 필요한 서버 기능을 담당하고, Supabase가 인증과 영구 데이터 저장을 담당하도록 해.

## 먼저 할 일
1. 현재 저장소와 파일 구조, package.json, 기존 기능을 살펴봐.
2. 첨부한 두 문서의 요구사항을 확인해.
3. 구현 순서와 변경할 파일을 간단히 제시해.
4. 그 후 계획 설명에서 멈추지 말고 실제 구현을 시작해.

## 반드시 지킬 제품 요구사항
- 로그인 기반 클라우드 저장
- 과목·카테고리·TODO 생성/수정/삭제
- 과목별 공부 타이머와 전체 공부 시간 집계
- TODO 마감일과 독립 일정을 함께 보여주는 월간 캘린더
- 오늘의 할 일, 진행률, 학습 통계를 보여주는 대시보드
- Pretendard 및 `design.md`의 시각 규칙
- 로딩/빈 상태/오류/성공 피드백
- 사용자별 데이터 접근 제어와 Supabase RLS
- 새로고침 이후 타이머 상태 복원, 자정 경계 처리, 중복 세션 방지

## Vercel + Supabase 설정
- `.env.example`을 작성하고 필요한 환경 변수와 각각의 용도를 문서화해.
- 실제 비밀 키를 코드나 Git에 넣지 마.
- DB schema를 `supabase/migrations/`의 SQL migration으로 관리해.
- Supabase Auth의 로컬/프로덕션 redirect URL 설정을 README에 설명해.
- RLS 정책을 만들고 사용자 간 데이터 접근 테스트를 추가해.
- Vercel 배포가 가능한 빌드 명령과 설정을 확인해.
- 무료 플랜의 사용량 제한 및 Supabase 비활성 프로젝트 일시정지 가능성을 문서화해.
- 계정 연결이나 환경 변수처럼 내가 직접 해야 하는 작업은 명확하게 구분해.
- 실제 배포를 수행하지 않았다면 배포 완료라고 말하지 마.

## 디자인 기준
`design.md`의 디자인 토큰과 규칙을 모든 페이지에 적용해. Pretendard, 간결한 카드형 대시보드, 절제된 포인트 컬러, 얇은 테두리와 충분한 여백을 사용해. 불필요한 그림자, 글로우, 과한 그라데이션, 장식용 차트는 사용하지 마. 토스의 정확한 화면이나 브랜드 자산을 복제하지 말고, 명료하고 정돈된 사용 경험만 참고해.

## 작업 방식
- 기존 프로젝트가 있으면 스택을 확인한 뒤 불필요한 재작성을 피한다.
- 실제 데이터와 임시 데이터의 차이를 명확히 한다.
- 단계별로 구현하고 각 단계마다 타입 검사, 린트, 테스트를 실행한다.
- 에러가 나면 원인을 확인하고 수정한다.
- 필요한 외부 설정이 없더라도 가능한 부분은 먼저 구현한다.
- 보안상 민감한 키를 클라이언트에 노출하지 않는다.
- 실제로 구현하지 않은 기능을 완료했다고 표현하지 않는다.
